# Unii Routes — แอพเลือกจุดส่งสำหรับคนขับ (สาขา 584)

โปรเจ็กต์ Google Apps Script ที่แยกขาดจากระบบ OPS เดิม — คนละลิงก์ คนละ deploy
คนละล็อกอิน และ**คนละไฟล์สเปรดชีต**

คนขับเปิดลิงก์เดียว เห็นแผนที่จุดส่งของวันนั้นเฉพาะโซนที่ตัวเองถือ กดจองเอง
ปิดงานเอง แอดมินใส่ PIN แล้วดูภาพรวม จัดการคนขับ วาดโซน และเคลียร์จุดที่มีปัญหา

## ใช้สองไฟล์ แยกหน้าที่กันเด็ดขาด

```
ไฟล์ของ Routes (สร้างใหม่)          ไฟล์ระบบ OPS (ของเดิม)
สคริปต์ผูกกับไฟล์นี้                  เปิดด้วย openById อ่านอย่างเดียว
├─ _ASSIGN    ← เขียน                ├─ คำสั่งซื้อ (gid 0)  ← อ่าน
├─ _DRIVERS   ← เขียน                ├─ API Import        ← ไม่แตะ
├─ _ZONES     ← เขียน                ├─ คำสั่งซื้อ VS      ← ไม่แตะ
├─ _PINFIX    ← เขียน                └─ ทุกแท็บของ OPS     ← ไม่แตะ
├─ _CONFIG    ← เขียน
└─ เมนู "Unii Routes" อยู่ที่ไฟล์นี้
```

ไฟล์ OPS จะไม่มีแท็บใหม่โผล่แม้แต่แท็บเดียว และไม่มีเมนูของโปรเจ็กต์นี้ไปขึ้น

---

## กฎเหล็กของโปรเจ็กต์นี้

1. **ไฟล์ OPS อ่านอย่างเดียว** — กันไว้สองชั้น: ฟังก์ชันเขียนทุกตัวใน `SheetIO.js`
   หา target ผ่าน `ownSheet_()` ซึ่งคืนได้เฉพาะแท็บในไฟล์ของ Routes เท่านั้น
   และยังบล็อกซ้ำอีกชั้นว่าต้องเป็นแท็บที่ขึ้นต้นด้วย `_`
   ไม่มีเส้นทางไหนในโค้ดที่เขียนลงไฟล์ OPS ได้เลย
2. **จัดโซนจากพิกัดเท่านั้น** — ไม่มีโค้ดบรรทัดไหนอ่านข้อความที่อยู่มาตัดสินโซน
   (ที่อยู่แสดงบนจอได้ แต่ไม่มีผลต่อการตัดสินใจ)
3. **ของไม่หายเงียบ** — จุดที่ไม่มีพิกัด / พิกัดหลุดกรอบ / ไม่ตกโซนไหนเลย
   ขึ้นในแท็บ "ต้องเคลียร์" ของแอดมินเสมอ และมีป้ายแดงบนหน้าภาพรวม

## ติดตั้งครั้งแรก

### 1. สร้างสเปรดชีตใหม่สำหรับ Routes

สร้าง Google Sheet ใหม่ ตั้งชื่อเช่น **"Unii Routes 584"**
(**อย่า**ใช้ไฟล์ Monthly Sheet ของ OPS — สคริปต์จะปฏิเสธและขึ้นข้อความเตือน)

ตั้งเขตเวลาให้ตรงกัน: `File` → `Settings` → Time zone = `(GMT+07:00) Bangkok`

### 2. ผูกสคริปต์กับไฟล์ใหม่

จากไฟล์ที่เพิ่งสร้าง → `Extensions` → `Apps Script` → ตั้งชื่อโปรเจ็กต์ว่า `Unii Routes`
คัดลอก Script ID จาก `Project Settings`

### 3. ดันโค้ดขึ้นด้วย clasp

```bash
npm install -g @google/clasp
clasp login
cp .clasp.json.example .clasp.json     # แล้วใส่ scriptId ที่คัดลอกมา
clasp push
```

### 4. สร้างแท็บและตั้ง PIN แอดมิน

กลับไปที่ไฟล์ Routes รีเฟรชหนึ่งครั้ง จะมีเมนู **Unii Routes** โผล่ขึ้นมา

`Unii Routes` → `ติดตั้ง / ตรวจสอบระบบ`

ครั้งแรกจะขึ้นหน้าขออนุญาตสิทธิ์ — กดอนุญาต (ดูหัวข้อ "สิทธิ์" ด้านล่างว่าขออะไรบ้าง)
จากนั้นจะ:

- สร้างแท็บ `_ASSIGN` `_DRIVERS` `_ZONES` `_PINFIX` `_CONFIG` พร้อมหัวตารางและ dropdown
- **ทดสอบการเชื่อมกับไฟล์ OPS ทันที** แล้วรายงานว่าอ่านแท็บอะไรได้ กี่แถว
  และมีคอลัมน์ไหนที่หาจากชื่อหัวตารางไม่เจอบ้าง — ถ้าสิทธิ์ไม่พอจะรู้ตรงนี้เลย
  ไม่ใช่ไปรู้ตอนคนขับเปิดแล้วเจอแผนที่ว่าง
- **แสดง PIN แอดมิน 4 หลักที่สุ่มให้ครั้งเดียว — จดไว้**
  (เปลี่ยนทีหลังได้จากเมนู `ตั้ง PIN แอดมินใหม่`)

รันซ้ำกี่ครั้งก็ได้ ไม่ทับข้อมูลเดิม สร้างเฉพาะสิ่งที่ยังขาด

### 5. Deploy เป็นเว็บแอพ

`Deploy` → `New deployment` → `Web app`

| ช่อง | ค่า |
|---|---|
| Execute as | **Me** (สคริปต์เข้าถึงชีตด้วยสิทธิ์ของคุณ คนขับไม่ต้องมีสิทธิ์ในไฟล์ไหนเลย) |
| Who has access | **Anyone** |

เอาลิงก์ `/exec` ที่ได้ส่งให้คนขับ บอกให้ Add to Home Screen

> "Anyone" หมายถึงใครก็เปิดลิงก์ได้ — ตัวที่กันข้อมูลจริงๆ คือ PIN + token ที่
> เซ็นด้วย HMAC ทุก endpoint ที่คืนข้อมูลลูกค้าตรวจ token ก่อนเสมอ

### 6. เพิ่มคนขับและวาดโซน

เปิดลิงก์ → `เข้าหน้าแอดมิน` → ใส่ PIN

- แท็บ **โซน**: วาด polygon บนแผนที่ (ตอนติดตั้งมีโซนตัวอย่าง Z1/Z2 แบ่งเชียงใหม่–ลำพูน
  ให้ก่อน วาดทับได้เลย) — แก้แล้วคนขับเห็นผลทันทีที่รีเฟรช ไม่ต้องแก้โค้ด
- แท็บ **คนขับ**: เพิ่มคนขับ ตั้ง PIN 4 หลัก เลือกโซนที่ถือ (เลือกได้หลายโซน)

## ทำอะไรได้บ้าง (ครบทั้ง 3 เฟส)

**คนขับ**
- เลือกวันที่ (วันนี้ / พรุ่งนี้ / ปฏิทิน) แผนที่เต็มจอ + รายการลากขึ้นดูได้
- เรียงจุดตามระยะทางจากตำแหน่งตัวเอง
- **จองจุด** — กดปุ่มเดียวได้ทั้งจุด (ทุกออเดอร์ของร้านนั้น) หมุดเปลี่ยนสีทันที
  ถ้ามีคนชิงไปก่อน ระบบจะย้อนกลับให้เองพร้อมบอกว่าใครได้ไป
- **ปล่อยคืน** เผื่อจองผิด ให้คนอื่นหยิบต่อ
- **ปิดงาน** — ส่งสำเร็จ / ส่งไม่สำเร็จ (เลือกเหตุผลจากลิสต์ + หมายเหตุ)
  จับ GPS เฉพาะจังหวะกดปุ่ม พร้อมข้อความบอกคนขับตรงๆ ว่าเก็บแค่ตอนนี้
- **"หมุดผิด — ใช้ตำแหน่งฉันตอนนี้"** ยืนหน้าร้านแล้วกดปุ่มเดียว
- สรุปท้ายวัน: ส่งแล้วกี่จุด ไม่สำเร็จกี่จุด เหลือกี่จุด เก็บเงินได้เท่าไหร่

**แอดมิน**
- ภาพรวมวันนี้ + งานของแต่ละคน (เห็นภาระงานไม่สมดุลทันที)
- ต้องเคลียร์: ไม่มีพิกัด / พิกัดน่าสงสัย / ยังไม่มีโซน / ยังไม่มีคนจอง
- **จัดการจุด**: มอบหมายให้คนขับคนไหนก็ได้ข้ามโซน, ดึงคืน,
  ปล่อยข้ามโซนให้ใครหยิบก็ได้, และลากหมุดแก้พิกัดบนแผนที่
- จัดการคนขับ + PIN + โซนที่ถือ, วาด/แก้ polygon, ดูและย้อนกลับหมุดที่ถูกแก้,
  หน้าตรวจระบบว่าอ่านคอลัมน์ไหนอยู่

ชุดทดสอบ 56 ข้อ รันจากเมนู `รันชุดทดสอบ`

## เรื่องที่ต้องรู้ก่อนแก้โค้ด

### คอลัมน์หาโดยชื่อหัวตาราง ไม่ใช่ตำแหน่ง

สเปกตั้งต้นบอกว่าคอลัมน์ G คือ `จำนวนรายการ` แต่ชีตจริง (ตรวจ 6/8/2026) คอลัมน์ G
คือสถานะการปริ๊น โค้ดจึงหาคอลัมน์จาก**ชื่อหัวตาราง**ก่อนเสมอ แล้วค่อยถอยไปใช้
ตำแหน่งเดิมถ้าหาชื่อไม่เจอ — ดู `ORDER_FIELDS` ใน `Config.js`

หน้าแอดมินแท็บ **ตรวจระบบ** แสดงว่าแต่ละฟิลด์ไปตกที่คอลัมน์ไหนและหาเจอด้วยวิธีอะไร
แถวไหนขึ้น "⚠ เดาจากตำแหน่งเดิม" แปลว่าหัวตารางในชีตถูกเปลี่ยนชื่อ ควรไปแก้
`ORDER_FIELDS` ให้ตรง

### หมุดรวมด้วยเบอร์โทรก่อน

`stop_key` เป็น `p:<9 หลักท้ายของเบอร์>` ถ้ามีเบอร์ ไม่งั้นถึงใช้พิกัดปัด 5 ตำแหน่ง

เหตุผล: ร้านเดียวกันสั่งสองออเดอร์ในวันเดียว พิกัดไม่ได้ตรงกันเป๊ะเสมอ (ออเดอร์เก่า
อาจเป็นพิกัดก่อนแก้หมุด) ถ้าจับกลุ่มด้วยพิกัดอย่างเดียวจะแตกเป็นสองหมุดซ้อนกัน
ซึ่งคือปัญหาที่ตั้งใจจะแก้พอดี และเบอร์โทรก็เป็นคีย์เดียวกับ `_PINFIX` อยู่แล้ว
ร้านคนละร้านที่อยู่ใกล้กันจะไม่ถูกรวมกันเด็ดขาด

### โซนล็อกตอนจอง ไม่ใช่ตอนสร้างงาน

จุดที่ยังไม่มีคนจอง = คำนวณโซนสดทุกครั้ง (แก้ polygon แล้วเห็นผลทันที)
จุดที่จองแล้ว = ใช้ `zone_id_locked` ที่บันทึกไว้ตอนจอง (ไม่มีใครโดนดึงงานออกจากมือ)
ได้ทั้งสองอย่างพร้อมกัน และไม่ต้องมีขั้นตอน "กดสร้างงานของวันนี้"

### การจองมีสองชั้น

1. `LockService` ครอบทุกการเขียน `_ASSIGN` — อ่านสดใหม่ (ไม่ใช้แคช) แล้วค่อยเขียน
2. `_ASSIGN` เป็น log ที่มีแต่การ append และตัดสินว่า **แถวแรกชนะ**

ชั้นที่ 2 คือตัวที่ทำให้ปลอดภัยจริง ไม่ใช่แค่ "ปกติก็ถูก" — ถ้าล็อกหมดเวลาแล้วมีสองแถว
หลุดเข้ามา ทุกคนที่อ่านยังได้คำตอบเดียวกันว่าใครได้ (คนที่แถวมาก่อน) ไม่ใช่ขึ้นกับว่าใครอ่านตอนไหน

ฝั่งหน้าจอทำ optimistic update — หมุดเปลี่ยนสีทันทีที่กด ถ้าเซิร์ฟเวอร์ปฏิเสธจะย้อนกลับ
พร้อมบอกว่าใครจองไปก่อน แล้วรีเฟรชให้เอง

### เกณฑ์ GPS บวกค่าความคลาดเคลื่อนของเครื่อง

ธง `far` ขึ้นเมื่อ `ระยะห่าง > 300 + accuracy ที่มือถือรายงาน` ไม่ใช่ 300 เมตรเปล่าๆ
มือถือกลางเมืองที่จับ wifi positioning รายงาน ±300–500 ม. เป็นเรื่องปกติ ถ้าไม่บวกค่านี้
รายการ "ต้องตรวจ" จะเต็มไปด้วยเคสปลอมจนแอดมินเลิกดู — และเคสจริงจะหายไปในกอง

**ไม่มีอะไรบล็อกการปิดงาน** ไม่ว่าจะห่างแค่ไหน ปฏิเสธสิทธิ์ หรือหาตำแหน่งไม่ได้
คนขับยืนอยู่หน้าร้านอยู่แล้ว และสาเหตุที่ `far` ส่วนใหญ่คือหมุดผิด ไม่ใช่คนขับผิด

### _ASSIGN โตทุกวัน จึงอ่านเฉพาะช่วงที่ต้องใช้

แท็บนี้ append อย่างเดียว วันละ ~100 แถว ถ้าอ่านทั้งแท็บทุก request จะช้าลงเรื่อยๆ
ตลอดอายุการใช้งาน โค้ดจึงสแกนคอลัมน์วันที่ก่อน แล้วอ่าน block เฉพาะช่วงแถวที่ตรง
(แถวของวันเดียวกันเกาะกลุ่มกันอยู่แล้วเพราะ append ตามเวลาจริง) — วิธีเดียวกับที่อ่านออเดอร์

### ประสิทธิภาพ

- อ่านคอลัมน์วันที่ก่อน 1 คอลัมน์ แล้วค่อยอ่าน block เฉพาะช่วงแถวที่ตรงวันที่
  ไม่เคยเรียก `getDataRange()`
- แคชผลต่อวันที่ 30 วินาที (`CACHE_SECONDS`) และ**ทุกการเขียนล้างแคชทันที**
  ผ่านตัวนับ `data_version` ที่อยู่ในคีย์แคช
- เขียนแบบ batch เสมอ ไม่มี `setValue()` ใน loop

### ข้อจำกัดที่รู้อยู่

- **Geolocation ในหน้าเว็บของ Apps Script** ทำงานผ่าน iframe ซ้อน บางเบราว์เซอร์บนมือถือ
  จะถามสิทธิ์ช้าหรือปฏิเสธ ระบบออกแบบให้ไม่มีอะไรพังถ้าไม่ได้สิทธิ์:
  ปิดงานได้ปกติ (บันทึกเป็น `denied`), เรียงตามระยะทางเป็นแค่ตัวช่วย
  มีอย่างเดียวที่ต้องใช้จริงคือปุ่ม "ใช้ตำแหน่งฉันตอนนี้" แก้หมุด
  ถ้าไม่ได้สิทธิ์จะขึ้นข้อความให้ไปเปิดสิทธิ์ก่อน ไม่ได้เงียบหาย
  ครั้งแรกที่ใช้ ให้คนขับกด "อนุญาต" ตอนเบราว์เซอร์ถาม แล้วเลือก "จำไว้"
- **สิทธิ์ (OAuth scope)**: เพราะต้องอ่านข้ามไฟล์ไปที่ไฟล์ OPS สคริปต์จึงต้องขอ
  `spreadsheets` (อ่าน–เขียนสเปรดชีต) ไม่ใช่ `spreadsheets.currentonly` แบบเดิม
  ในทางเทคนิคแปลว่าสคริปต์เข้าถึงสเปรดชีตอื่นที่บัญชีคนกด Deploy มีสิทธิ์ได้
  — นี่คือราคาที่ต้องจ่ายเพื่อแลกกับการแยกไฟล์ Google ไม่มี scope แบบ "เฉพาะสองไฟล์นี้"
  สิ่งที่กันจริงคือตัวโค้ด: เขียนได้เฉพาะแท็บ `_` ในไฟล์ที่ผูกอยู่เท่านั้น
- **โควต้า Apps Script**: คนขับ 5 คน รีเฟรชทุก 20 วินาที ≈ 900 เรียก/ชม.
  ยังห่างจากเพดาน แต่ถ้าเพิ่มคนขับเยอะควรขยับ `REFRESH_SECONDS` ใน `_CONFIG`
- **ช่องว่างระหว่าง polygon** ทำให้จุดตกเป็น UNASSIGNED และคนขับจะไม่เห็น
  ต้องดูป้ายแดง "ต้องเคลียร์" ทุกเช้าก่อนปล่อยรถ

| `Util.js` | แปลงวันที่/ตัวเลข/เบอร์โทรจากข้อมูลที่กรอกมือ |
| `Geo.js` | ray casting, haversine, อ่าน GeoJSON |
| `Auth.js` | แฮช PIN, token เซ็น HMAC, จำกัดการกรอกผิด |
| `Drivers.js` `Zones.js` `PinFix.js` | อ่าน/เขียนแท็บของตัวเอง |
| `Orders.js` | หัวใจ: วันที่ → กรอง → พิกัด → รวมหมุด → โซน → ใครจอง |
| `Assign.js` | จอง / ปล่อยคืน / ปิดงาน + GPS / คำสั่งแอดมินรายจุด |
| `Api.js` | endpoint ทั้งหมดที่เบราว์เซอร์เรียกได้ |
| `Setup.js` | สร้างแท็บ + เมนูในสเปรดชีต |
| `Tests.js` | ชุดทดสอบตรรกะที่ผิดแล้วเงียบ |
| `Index.html` `Styles.html` | โครงหน้าและสไตล์ (มือถือมาก่อน ปุ่ม ≥44px) |
| `CoreJs.html` `DriverJs.html` `AdminJs.html` | ฝั่งเบราว์เซอร์ vanilla JS |
